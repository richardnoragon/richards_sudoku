# Maintainer roles

## Alpha alignment

For [Alpha](alpha.md), core maintainers review architecture stability, QA reviews
major workflows, and an independent developer demonstrates the DOC-09 handoff.
Record actual participants and evidence before changing the stage; these role
descriptions do not claim that anyone has completed the review.

This file describes responsibilities carried forward from the governance plan.
Named role assignments and approvals must be recorded in the relevant PR or release;
this document does not appoint people or claim that approvals have occurred.

| Role | Responsibility |
| --- | --- |
| Core maintainers | Architecture, constitution, disputes, and final release decisions |
| Variant maintainers | Variant rules, generators, validation, and fixtures |
| QA/testing lead | Test coverage, reproducibility, and Appendix B review |
| UX lead | Accessibility, controls, interaction, and Appendix C review |
| Performance lead | Budgets, profiling, regressions, and Appendix D review |
| Persistence lead | Schema compatibility, migrations, and Appendix E review |
| Release manager | Coordinate evidence, version updates, release notes, and publication |

A maintainer may fill multiple roles; record the responsible person and decision
for each required sign-off. Follow [GOVERNANCE.md](GOVERNANCE.md),
[the lifecycle table](C.L.E.A.R.%20Lifecycle%20Table%20per%20Appendix.md), and
[RELEASE_CHECKLIST.md](RELEASE_CHECKLIST.md).
